# 設計の考え方（RATIONALE）

> **これは実験的な参照仕様です。いずれの標準化団体の公式仕様でもありません。**

判断するのは利用者です。このツールは下調べと記録を担います。

この文書は、貿易用プロファイル（trade-agent-profile）v0.1 がなぜ今の形なのかと、採らなかった案を説明する。決まりそのものは `docs/PROFILE.md` にある。

## 1. 目的

荷主・フォワーダー・通関業者・銀行の AI エージェントが、決まった形のデータで貿易の用件（見積、ブッキング、書類の提出、食い違いの通知、申告の下書き、承認）をやり取りできるようにする。想定する使い手は、自社の業務の AI をほかの会社とつなぎたい、小さな通関業者やフォワーダーの開発担当者である。

## 2. 3つの方針

### 2.1 新しい通信方式を作らない

エージェント同士の会話には A2A を、AI に道具を出すには MCP を使う。どちらも公開の仕様と公式の部品がある。このプロファイルが定めるのは、その上に載せるデータの形（共通データ契約とメッセージの型）、名前の付け方、適合テストだけである。通信方式を新しく作ると、相手も同じものを作らなければならず、つながる相手が増えない。

### 2.2 中立を保つ

TradeLens（Maersk と IBM の貿易プラットフォーム）は、2022年11月29日に終了が発表され、2023年の第1四半期の終わりまでに止める予定とされた。発表では、業界全体の協力が得られなかったことが理由に挙げられている。この教訓から、次のようにした。

- 中央のサーバーを置かない。参加する会社は、それぞれのエージェントを自分で動かし、相手と直接やり取りする。
- 既存の標準に対応づける（`docs/MAPPING.md`）。独自の項目名を押しつけない。
- 公開するときは、誰でも使える条件にする（コード・スキーマ・見本・適合テストは Apache-2.0、文書は CC BY 4.0）。

### 2.3 第三者が自分で確かめられるようにする

決まりを文章で書くだけでは、実装どうしが本当につながるかは分からない。そこで、外から試せる適合テストを置いた。相手とは A2A で通信するだけなので、実装の言語や中の作りは問わない。決まりを足すときは、その決まりを破った実装が不合格になることも確かめる。

## 3. 主な設計の判断

| 判断 | 理由 | 採らなかった案 |
|---|---|---|
| 1つのメッセージを、A2A の Message の Part 1つで送る（`data` に封筒） | 受け手は Part を1つ読めばよく、検証の単位がはっきりする。A2A の Part の `data` は JSON の値を運べる（A2A 4.1.6） | 項目を複数の Part に分ける。文章の Part に入れる |
| 会話を束ねる値（`correlation_id`）を封筒の中に持つ | A2A の `contextId` は受け手が振るもので、送り手が自分で決めることは勧められていない（A2A 3.4.1） | `contextId` をそのまま使う |
| `message_id`（UUID）で二重処理を防ぐ。同じ id で中身が違えば断る | 通信が途切れたときに、送り手が安心して送り直せる（A2A 3.3.1） | 受け手が届くたびに処理する |
| 金額・数量・重量を、10進数の文字列で持つ | JSON の数は、部品によっては倍精度の小数として運ばれ、桁の多い数が丸められることがある | JSON の数で持つ |
| 照合済みの正しい値（最上位の値）と、書類に書いてあった値（`documents[].fields`）を分けて持つ | 書類どうしの食い違いを、根拠（ページと位置）つきで見つけられる | 値を1か所だけに持つ |
| 検証は規則だけで行い、AI を使わない | 同じ入力にいつも同じ答えを返し、理由を説明できる。AI が出した値も、規則で検算できる | AI に判定させる |
| プロファイルを A2A の拡張として AgentCard で宣言し、必須にもできる | 相手がこのプロファイルを話せるかを、やり取りの前に確かめられる（A2A 4.6、3.3.4） | 封筒の中だけで名乗る |
| エラーを「コードと場所」の組で表す | 説明文を直しても、プログラムの判定は変わらない。日本語と英語の両方で説明できる | 説明文だけで知らせる |

## 4. 採らなかったほかの方式

- **IBM の Agent Communication Protocol（ACP）**：2025年8月、Linux Foundation の LF AI & Data で、ACP が A2A に合流することが発表され、ACP の開発は縮小された。そのため、A2A を使う。
- **NLIP（Natural Language Interaction Protocol、ECMA-430 第1版、2025年12月）**：AI エージェント同士、または人と AI エージェントの間の、アプリケーションの層の通信の決まりで、名前のとおり自然言語でのやり取りを扱う。このプロファイルの目的は、構造化したデータを厳密に照合することで、会話の運び方は A2A に任せている。役割が違うので、v0.1 では対応づけない。
- **書類の真正性を保証する仕組み（TradeTrust など）**：書類が改ざんされていないことの証明は扱わない。項目の対応だけを `docs/MAPPING.md` に示す。
- **中央のプラットフォーム**：第2.2節の理由で置かない。

## 5. これから決めること

`docs/PROFILE.md` 第11節にまとめてある（識別 URI の確定、認証、ストリーミングとプッシュ通知、銀行の役割の見本など）。
