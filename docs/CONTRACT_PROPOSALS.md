## 案26 からの提案（2026-11-24 に受け取り、同じ日に検討）

案26（船積みのデータから貿易書類を作るプロジェクト）が、契約 v0.1.0 を使ってみて出した提案である。「案26 の番号」は案26 の中の呼び名で、案26 はいま、どれも `ext.p26` の下に置いて使っている。

検討の結果は「0.1.1 で取り入れる」「保留」「取り入れない」「見送り」のどれかにした。**取り入れると決めた3件（P-009〜P-011）は、2026-11-24 に 0.1.1 として反映した。** 変更点は `dist/contract-v0.1/CHANGELOG.md`、読み方は `dist/contract-v0.1/README.ja.md` にある。

### 0.1.1 で足した項目

| 項目 | 形 | null・空 | 意味 |
|---|---|---|---|
| `parties.notify_parties` | 当事者（`name`・`address`・`country`）の一覧 | 0件可。3件まで | 通知先。いないとき・分からないときは、空の一覧にする |
| `trade_terms.freight_amount` | 金額（小数2桁の文字列） | null 可 | インボイスの金額（`totals.amount`）に含まれている運賃の額。含まれていないとき・分からないときは null |
| `trade_terms.insurance_premium_amount` | 金額（小数2桁の文字列） | null 可 | インボイスの金額に含まれている保険料の額。含まれていないとき・分からないときは null |
| `transport.vessel_name` | 文字列 | null 可 | 積み地を出る本船の名前。海上輸送でないときは null |
| `transport.voyage_number` | 文字列 | null 可 | その本船の航海番号 |
| `transport.booking_number` | 文字列 | null 可 | 運送人のブッキング番号 |

- 0.1.0 のほかの項目と同じく、項目そのものは省けない（分からなければ null か空の一覧）。
- 運賃や保険料を、インボイスとは別に、または別の通貨で支払った場合（輸入で、FOB の値段に運賃を足して考える場合など）は、0.1.1 では扱わない。要る案が出たら、通貨つきの項目を足すことを検討する。
- 船名と航海番号は1組、ブッキング番号は1つだけを持つ。積み替えがあって本船が2つ以上ある場合や、ブッキングが2つ以上ある場合は、0.1.1 では扱わない（DCSA は、どちらも一覧で持つ）。
- あわせて、P-008（数の扱いの書き足し）を、配布物の説明に入れた。
- 規則（検査数字、合計、日付の前後など）とエラーのコードは、増やしていない。「運賃と保険料の合計が、インボイスの金額を超えていないか」を調べる規則は、足すかどうかを検討したが、0.1.1 には入れていない（項目を足すだけにとどめた）。

### 版を上げるときの決まり（互換）

案26 の問い：「項目は省けない」という決まりのまま項目を足すと、0.1.0 のデータは 0.1.1 の形では誤りになる。検証が版ごとに形を選ぶのか、足した項目だけは省いてよいことにするのか。

決めたこと（0.1.1 で、このとおりにした）：

1. **検証は、データに書いてある `contract_version` に合わせて形を選ぶ。** 0.1.1 を出したあとも、0.1.0 のデータは 0.1.0 の形で検証して合格にする。古いデータを書き換える必要はない。形を選ぶのはスキーマ自身なので、スキーマだけで調べる場合も、版ごとに呼び分けなくてよい（スキーマの `$id` は変えていない）。
2. **「足した項目だけは省いてよい」とはしない。** この契約では、null は「書類にない・まだ分からない」、項目そのものがないのは「その版では扱わない」を意味する。0.1.1 のデータで項目が欠けていてよいことにすると、どちらなのか区別できなくなる。
3. **0.1.0 から 0.1.1 への書き換えは、機械的にできるようにする。** `contract_version` を書き換え、足した項目を null（通知先は空の一覧）で足すだけで、ほかの値は変えない。そのための道具は `scripts/upgrade.py`。`ext` の下に置いていた値を正式の項目へ移すのは、それぞれの案が行う。
4. 0.1.0 しか知らない受け手は、0.1.1 のデータを「版の不一致」として断る（いまの決まりのまま）。

### 今までの提案との関係

- P-002（通知先）は、P-009 にまとめた。
- P-003（通貨ごとの小数の桁）と P-006（数量 × 単価 ＝ 金額の確認）：案26 は、明細の金額を「数量 × 単価」で計算し、通貨ごとの小数の桁（円は0桁、ドルは2桁）で四捨五入してから、契約の決まりどおり小数2桁で書いている（丸め方は、案26 の仮の決まり）。丸め方を決めるときの参考として記録する。どちらも、未検討のままである。
